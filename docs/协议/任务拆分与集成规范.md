# 任务拆分与集成规范（v1，2026-10-13）

> 目的：一件活拆给多个子 agent（必要时到孙 agent），保证各自交回来的东西**能直接拼在一起用**。
> 核心思想：**先定契约，再拆活；交接只认结构化的产物和披露，不认口头转述；每一层只对自己的下一层负责。**
> 依据：MAST（多 agent 失败的 14 种模式）、Cognition《Don't Build Multi-Agents》、Anthropic 多 agent 研究系统、Magentic-One、Google A2A、GitHub Spec Kit。出处见文末。

---

## 一、拆不拆（默认不拆）
研究的共同结论：在同样的 token 预算下，推理类任务用一个 agent 不比用多个差；**只有能并行的活，多 agent 才占优**。另外，每多一次交接，信息就会损失一点。

按下面顺序判断，**有一条是"否"就不拆**：
1. 能不能分成几块，**每块交出一个能单独验收的产物**？（按产物来分，不按步骤来分）
2. 块与块之间的耦合度是不是 C0 或 C1？（见《任务分类标准》；C2 不拆）
3. 块与块之间的接口能不能**写成一页纸的契约**？
4. 拆开以后，总耗时或总成本是不是确实更低，或者质量更高（比如要用两家模型交叉）？

拆的时候：**按产物边界拆，不按工序拆**。一个子任务交出一个完整、可验收的东西（一个脚本加它的测试、一份数据文件），而不是"你写前半、他写后半"。

## 二、契约先行（拆之前必须做）
**为什么**：Cognition 的例子：两个子 agent 一个画鸟、一个画背景，各自做了合理但互相冲突的决定（风格完全不同）。**每个动作都隐含着决策**，事先没定死的地方，子 agent 就会各自做主。

父级在派活**之前**，先写一份**共享决策记录**（模板：`模板/共享决策记录.md`），至少包括：
| 项 | 内容 |
|---|---|
| 目标与不做什么 | 一句话目标；明确哪些不在这次范围内 |
| 接口与数据格式 | 每个交接文件的精确格式：字段、分隔符、编码、排序、空值和异常怎么表示；**附一个小样例** |
| 坏输入怎么办 | 读别人交来的文件遇到不合格式：**默认报错退出、报出行号**，不准悄悄容忍（容忍会吞掉上游的错）；读原始数据遇到坏行跳不跳、跳过的算不算进汇总，也要写明（2026-10-13 实战补） |
| 共同前提 | 所有子任务都必须遵守的事实和规则（比如"切词必须和引擎用同一套词库、同一种算法"） |
| 文件归属 | 每个文件只归一个 agent 写（单写者原则）；共用文件只能由集成者改 |
| 命名与风格 | 函数名、命令行参数、语言版本、能用哪些依赖 |
| 已知未定 | 还没想清楚的点；遇到时一律上报，不准自己定 |

**每个子任务都带上这份记录的全文**，不能只给摘要（Cognition：只拿到摘要的子 agent 会误读任务）。

## 三、子任务卡（模板：`模板/子任务卡.md`）
每张卡必须写清（依据 Anthropic 的派活要求：目标、输出格式、工具、边界）：
- **分类与难度分析**（按《任务分类标准》）
- **目标**：一句话
- **共享决策记录**：全文附上，或者给出绝对路径并要求先读
- **输入**：放在 `输入/` 下的文件，各是什么
- **产物**：文件名和格式（必须和契约一致）
- **能动的范围**：只能写哪些文件
- **验收标准**：写成机器能检查的条件
- **预算**：步数、超时、思考档位
- **允许再往下拆几层**：默认 0
- **交付说明格式**：最后的回复按 `模板/交付说明.md` 写（含决策披露）

## 四、层级（默认 1 层，必要时最多 2 层）
- **默认只拆 1 层**：父级 → 子 agent。
- **拆到孙级（第 2 层）**，必须在子任务卡里写明"允许再拆 1 层"，而且：
  1. 子 agent 自己要为孙级先写一份**追加的**共享决策记录：只能在父级契约的基础上**增加**细节，**不能推翻或改动**父级的任何一条；
  2. **子 agent 负责把孙级的结果拼好、按集成三关验收过，再交给父级**。父级只跟子 agent 打交道（每一层只对自己的下一层负责）；
  3. 孙级发现契约不够用或者冲突，上报给子 agent；子 agent 自己裁决不了的，再往上报。
- **不允许第 3 层**。框架层面也有限制：工人都在沙箱里，不能联网，本身派不出新的工人；需要再拆时由子 agent 申请，大脑来派。

## 五、交付说明与决策披露（模板：`模板/交付说明.md`）
每个子 agent 的最后回复（会写进 `结果.txt`）必须包括：
1. **结论**：做完没有，一句话
2. **产物清单**：文件名，和契约里的哪一项对应
3. **自检结果**：跑了哪些测试，实际输出是什么（没跑就写没跑）
4. **决策披露**（最关键）：
   - 我做了哪些**契约里没写**的决定（比如遇到空行怎么处理、排序怎么破平局）
   - 哪些地方**偏离了契约**，为什么
   - 有哪些**没解决的问题**
5. **状态**：完成 / 需要输入（说明缺什么） / 失败（说明原因）

"需要输入"状态参照 Google A2A 的任务状态：遇到契约不够用时，**停下来报告缺什么，不准自己猜着做**（对应 MAST 失败模式"没有请求澄清"）。

## 六、集成三关（父级拼装时必须逐关过）
| 关 | 检查什么 | 怎么检查 |
|---|---|---|
| ① 契约关 | 每份产物的格式、接口是否和契约一致 | 用脚本校验格式；拿契约里的样例跑一遍 |
| ② 一致关 | 各子任务的**决策披露**有没有互相冲突；命名、假设是否一致 | 把各份决策披露放在一起逐条对照；有冲突就裁决，并把结论写回共享决策记录 |
| ③ 端到端关 | 拼起来以后整体对不对 | 跑完整流程、跑测试、对考卷；**V1 的活，大脑能用几十行写出参考实现时就写一个，拿来逐字节对比**（实战里这一步把第③关变成了一条命令）；写不出来就交给另一家模型交叉审 |

任何一关没过：开新轮次重做那一块（最多重试 2 次），或者改契约后重新派。

## 七、台账（每个项目一份，依据 Magentic-One）
- **任务台账**（`模板/任务台账.md`）：已知事实、要查的事实、要推断的、目前的猜测、计划。计划变了就更新。
- **进度台账**（`模板/进度台账.md`）：每轮记一行：完成了吗？在打转吗？有进展吗？下一步交给谁、做什么？
- **连续两轮没有进展，或者在打转** → 停下来重新规划（更新任务台账），必要时问 用户。

## 八、MAST 自查清单（14 种失败模式 → 本规范的对策）
| MAST 失败模式 | 对策 |
|---|---|
| 1.1 不遵守任务规格 | 子任务卡写明产物和验收标准；契约关逐项检查 |
| 1.2 不遵守角色规格 | 卡上写明能动的范围；沙箱硬限制；执行者规则（AGENTS.md） |
| 1.3 重复步骤 | 卡上设步数和超时；进度台账检查"在打转吗" |
| 1.4 丢失对话历史 | 关键信息落在文件里（共享决策记录、台账），不靠记忆 |
| 1.5 不知道什么时候算完 | 验收标准写成可检查的条件；交付说明必须给出状态 |
| 2.1 对话被重置 | 每轮开新目录，从台账和契约恢复上下文 |
| 2.2 没有请求澄清 | "需要输入"状态；契约里的"已知未定"一律上报 |
| 2.3 偏离任务 | 目标写成一句话，"不做什么"也写明；验收时对照 |
| 2.4 隐瞒信息 | 决策披露是必填项；产物落盘，原样交接 |
| 2.5 忽视别人的输入 | 子任务卡要求先读契约全文；一致关检查 |
| 2.6 推理和行动不一致 | 交付说明里的自检结果必须是实际跑出来的输出；父级复跑核对 |
| 3.1 过早结束 | 端到端关通过之前不算完成 |
| 3.2 没有验证或验证不全 | 集成三关缺一不可；工人的自述不算证据 |
| 3.3 验证错误 | 关键产出交给另一家模型交叉审；父级自己复跑测试 |

## 九、和现有设施的关系
- 派活入口、账本、沙箱、回执、看板、表现记录：见 [`大脑手册.md`](../../大脑手册.md)（任何 agent 当大脑都照它做）。
- 输入文件：派活前设环境变量 `WORKER_INPUT_DIR=<目录>`，执行脚本会把它的内容复制到本轮目录的 `输入/` 里（工人只能在本轮目录里读写）。
- 表现记录要加上分类维度：`类型`、`难度`、`耦合度`、`可验证性`。

## 十、实战记录
- **2026-10-13 CL-20261013-02**（切词 + 二元统计，A 用 DeepSeek v4-pro，B 用 MiMo，两边互相看不到）：两边都一次通过集成三关，拼起来和参考答案逐字节一致，合计约 $0.085、5 分钟。契约里写死的点（多音词次数、未登录单字、标点、平局、排序）两边都没有各自做主。决策披露起了作用：A 主动报出"坏行算不算总数"，B 主动报出"畸形行悄悄当空"，后者暴露了契约的空白（已补"坏输入怎么办"一行）。
